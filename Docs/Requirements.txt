/*
    Gestione inventario laboratorio: Tracciamento delle attrezzature (es PC, componentistica)
    in un laboratorio informatico. CRUD item, gestione "prestiti" (chi ha preso cosa), stato
    dell'oggetto (disponibile, in prestito, rotto), storico manutenzione
*/

========================================
ANALISI DEI REQUISITI
========================================

ATTORI DEL SISTEMA:
    - Utenti: Gestisce oggetti, prestiti, configurazioni sistema
    - Clienti: Richiedono prestiti
REQUISITI FUNZIONALI:

RF1. GESTIONE INVENTARIO OGGETTI
    RF1.1 Visualizzazione oggetti
        - Lista completa di tutte le attrezzature
        - Ricerca per nome, codice identificativo, marca/modello
        - Filtri combinabili:
            * Stato (disponibile, in prestito, in manutenzione, rotto, fuori servizio)
            * Tipologia (PC, componente hardware, periferica, altro)
            * Quantità disponibile
            * Ubicazione nel laboratorio
    
    RF1.2 Operazioni CRUD oggetti (solo Amministratore)
        - Creazione nuovo oggetto con campi:
            * Codice identificativo univoco
            * Nome e descrizione
            * Tipologia
            * Marca e modello
            * Data acquisto e prezzo
            * Stato iniziale
            * Ubicazione
            * Note
        - Modifica informazioni oggetto esistente
        - Rimozione logica oggetto (non cancellazione fisica)
        - Cambio stato oggetto

RF2. GESTIONE PRESTITI
    RF2.1 Visualizzazione prestiti
        - Lista prestiti attivi e storico
        - Filtri combinabili:
            * Data inizio/fine prestito
            * Cliente
            * Tipologia oggetto
            * Stato prestito (attivo, scaduto, completato, annullato)
    
    RF2.2 Operazioni prestiti (solo Amministratore)
        - Creazione nuovo prestito:
            * Selezione cliente
            * Selezione oggetto/i (max 5 oggetti per prestito)
            * Data inizio e data prevista restituzione
            * Note aggiuntive
        - Registrazione restituzione prestito
        - Modifica date prestito
            - Base: prenotazione senza allungamento
            - Avanzato: prenotazione con allungamento
        - Annullamento prestito
        - Segnalazione oggetto danneggiato al rientro -> damaged e' un campo di LoanedObjects che viene inizializzato a false di default
            e puo' essere messo a true nel momento della restituzione e successivamente, se true, bisogna aggiornare lo stato dell'oggetto in Objects
    
    RF2.3 Vincoli prestiti
        - Massimo 5 oggetti contemporaneamente per utente
        - Durata massima prestito: 30 giorni
        - Non è possibile prestare oggetti in stato "rotto" o "in manutenzione"
        - Invio notifica automatica 3 giorni prima della scadenza
        - Blocco nuovi prestiti per utenti con prestiti scaduti o che hanno rotto x oggetti

RF3. STORICO MANUTENZIONE
    RF3.1 Registrazione interventi (Amministratore)
        - Data intervento
        - Tipo intervento (riparazione, manutenzione preventiva, upgrade, sostituzione)
        - Tecnico responsabile
        - Descrizione problema e soluzione e parti sostituite
            - IDEA: tecnico come utente a parte, che ha accesso a tutti gli oggetti in manutenzione assegnati a lui, 
                    Possibilità di aggiungere nella manutenzione le operazioni effettuate e modificare gli oggetti 
    
    RF3.2 Visualizzazione storico
        - Lista completa interventi per oggetto
        - Filtri per data, tipo intervento
        - Calcolo costi totali manutenzione per oggetto

RF4. STORICO OGGETTI
    RF4.1 Tracciamento completo
        - Storico prestiti associati all'oggetto
        - Calcolo tempo totale in prestito
        - Numero totale prestiti effettuati

RF5. GESTIONE CLIENTI
    RF5.1 Operazioni (solo Amministratore)
        - Creazione cliente (nome, cognome, email)
        - Modifica informazioni cliente
        - Blocco/sblocco cliente (impedisce nuovi prestiti)
            - L'amministratore deciderà quando bloccare un utente e per quanto tempo, in automatico verrà sbloccato in data x
        - Visualizzazione lista clienti 


RF6. AUTENTICAZIONE E AUTORIZZAZIONE
    - Login con username e password
    - Logout
    - Gestione sessioni con logout obbligatorio
    

========================================
REQUISITI NON FUNZIONALI
========================================

RNF1. SICUREZZA
    - Autenticazione obbligatoria per accesso al sistema
    - Password criptate (hashing con salt)
    - Log delle operazioni critiche (chi ha fatto cosa e quando)
    - Amministratore può gestire prestiti, oggetti e clienti

RNF2. AFFIDABILITÀ E CONSISTENZA DATI
    - Il sistema deve garantire consistenza dei dati (transazioni atomiche)
    - Backup automatico giornaliero del database
    - Validazione input utente per prevenire dati inconsistenti
    - Gestione errori con messaggi comprensibili
    - Integrità referenziale nel database

RNF3. PERFORMANCE
    - Tempo di risposta < 2 secondi per operazioni comuni
    - Ricerca oggetti deve completarsi in < 1 secondo con fino a 10.000 oggetti
    - Caricamento lista prestiti < 1.5 secondi

RNF4. USABILITÀ
    - Interfaccia intuitiva e user-friendly
    - Messaggi di errore chiari e propositivi
    - Conferma per operazioni critiche (eliminazione, blocco utente)
    - Supporto ricerca rapida con autocomplete?

RNF5. MANUTENIBILITÀ (DA RIVEDERE CON DESIGN PATTERN ETC)
    - Codice deve seguire convenzioni
    - Architettura a layer (Presentation, Business Logic, Data Access)
    - Documentazione JavaDoc
    - Design patterns appropriati (MVC, DAO, Factory)
    - Code coverage test > 70%
    - Naming convention chiaro e consistente

RNF6. PORTABILITÀ
    - Browser (Chrome, Firefox)

RNF7. STANDARD E CONFORMITÀ
    - Gestione date in formato ISO 8601
    - Log in formato strutturato (JSON)
    - Versionamento codice con Git

RNF8. SCALABILITÀ
    - Architettura modulare per future estensioni
    - Possibilità di aggiungere nuove tipologie oggetti
